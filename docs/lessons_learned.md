# Lessons Learned

## 2026-10-30 麻雀ルールは記憶で書かない

- 自分の記憶で書いた Mリーグのルール表が、2項目で逆だった（切り上げ満貫・数え役満）
- **次は**: ルールの既定値は、出典 URL と確認日が付いたものだけを要件やエンジンに入れる。一次情報が読めない日は「要確認」として分けておき、エンジンには組み込まない
- 同じ日に 110符1翻 でも同じ失敗をしたため、`.claude/rules/mahjong-rules.md` に昇格した

## 2026-10-30 ローカルで通っても、CI の型チェックは落ちる

- `tsc --noEmit` がローカルでは通り、CI では `Cannot find name 'LayoutProps'` で落ちた。`LayoutProps` などは Next.js が `.next/types` に生成する型で、ビルド前の CI には無い
- **次は**: 型チェックは `npm run typecheck`（`next typegen` → `tsc`）だけを使う。「ローカルで通った」は、新しく clone した環境で同じ順番に通してから言う

## 2026-10-30 端末の文字化けを、ファイルの文字化けと取り違えない

- 公式ページの保存版を Python で読んで端末に出したところ、日本語が化けた。ファイルが Shift_JIS だと思い込んで cp932 で読み直したら、ファイルに書き出した文字列の方が壊れた。実際のファイルは宣言どおり UTF-8 で、化けていたのは Windows の端末出力だけだった
- **次は**: 文字化けを見たら、まず `charset` の宣言とバイト列を確かめる。中身を確かめたいときは、端末に出さずにファイルへ書いて読む（`python -X utf8` を使う）

## 2026-10-30 Vitest で globals を使わないなら、cleanup を自分で呼ぶ

- 画面のテストを2件目から書いたところ、前のテストで描画した画面が残っていて「同じ名前のラジオボタンが複数ある」と落ちた。Testing Library の自動 cleanup は `afterEach` がグローバルにあるときだけ動き、この雛形は `globals: false` だった
- **次は**: `vitest.setup.ts` で `afterEach(cleanup)` を呼ぶ（設定済み）。雛形の画面テストが1件しかない間は、この不具合は表に出ない
